# SpecDriven Project Template

## Назначение

Шаблон для быстрого старта проектов с **SpecDriven** подходом — разработкой, управляемой спецификациями. Все изменения начинаются с написания или обновления спецификации, затем следует реализация и аудит соответствия.

---

## Основные каталоги

| Каталог | Назначение |
|---|---|
| `specs/` | Спецификации поведения. Структура: `specs/{domain}/{spec-id}-spec.md` |
| `docs/` | Документация проекта |
| `docs/architecture.md` | Структура проекта, зависимости, архитектурные решения (ADR) |
| `docs/modules/` | Документация модулей |
| `docs/packages/` | Документация пакетов |
| `docs/testing/` | Документация тестирования |
| `guidelines/` | Гайдлайны проекта |
| `guidelines/specification-guidelines.md` | Правила написания спецификаций |
| `guidelines/implementation-guidelines.md` | Правила реализации кода по спецификациям |
| `guidelines/documentation-guidelines.md` | Правила создания и поддержки документации |
| `guidelines/gigacode-md-guidelines.md` | Правила наполнения и обновления `GIGACODE.md` |

---

## Доступные скиллы

| Скилл | Назначение |
|---|---|
| `doc-sync` | Синхронизация документации с кодом |
| `spec-edit` | Создание и обновление спецификаций |
| `spec-impl` | Реализация кода по спецификации |
| `spec-audit` | Аудит соответствия spec ↔ код ↔ тесты ↔ docs |
| `template-init` | Интерактивная инициализация нового проекта (язык, сборка, гайдлайны) |
| `skill-edit` | Создание и редактирование скиллов в проекте |
| `skill-audit` | Аудит и рефакторинг скиллов (структура, дублирование, согласованность) |
