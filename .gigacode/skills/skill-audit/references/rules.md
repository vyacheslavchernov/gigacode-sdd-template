# Rules — Skill Audit

Правила рефакторинга скиллов.

See [`SKILL.md`](../SKILL.md) -- overview and scenarios.

---

## 1. Разделение SKILL.md

Перенеси в `references/` следующие секции из SKILL.md:

| Секция в SKILL.md | Куда перенести |
|---|---|
| Детальный workflow (пошаговые шаги) | `references/workflows.md` |
| Примеры (хорошие/плохие) | `references/examples.md` |
| Шаблоны (файлы, YAML, отчёты) | `references/templates.md` |
| Чек-листы и таблицы статусов | `references/checklists.md` |
| Сценарии с большим количеством шагов | Оставить в SKILL.md как краткое описание + ссылка на workflows.md |

## 2. Что ОСТАВЛЯТЬ в SKILL.md

- Фронтматтер (`name`, `description`, `last_updated`)
- Одно-двухпредложное описание назначения скилла
- Список сценариев (кратко, 1 строка на сценарий)
- Ссылки на `references/*`
- Ссылки на `guidelines/*` проекта
- Критические правила (ВСЕГДА/НИКОГДА)
- Краткий чек-лист завершения (если <= 10 строк)

## 3. Что УДАЛЯТЬ из SKILL.md

- Полные пошаговые workflow (-> workflows.md)
- Полные примеры с кодом (-> examples.md)
- Шаблоны файлов (-> templates.md)

- Развёрнутые чек-листы (-> checklists.md)

## 4. Кросс-ссылки

Каждый тип контента — отдельная секция в SKILL.md. Ссылки на `references/*` размещаются в соответствующих секциях:

**SKILL.md -> references/:**

```markdown
## Workflow

Детальный пошаговый workflow — в [`references/workflows.md`](references/workflows.md).

## Шаблоны

Шаблоны файлов и фронтматтеров — в [`references/templates.md`](references/templates.md).

## Примеры

Примеры до и после рефакторинга — в [`references/examples.md`](references/examples.md).

## Checklists

Чек-лист аудита — в [`references/checklists.md`](references/checklists.md).
```

> **Правило:** Если файл `references/prompts.md` не нужен — секцию `## Prompts` не создавай. Каждая секция в SKILL.md должна ссылаться на существующий файл в `references/`.

**references/ -> SKILL.md:**

```markdown
# Workflows -- {Skill Name}

See [`SKILL.md`](../SKILL.md) -- overview and scenarios.
```

## 5. Область действия

Работай **только** с каталогом скилла, который указан в запросе пользователя.

**Исключения:**
- Явное указание примеров (другие скиллы как reference)
- Необходимость обратиться к документации проекта (`docs/`) или гайдлайнам (`guidelines/`) для проверки дублирования контента

## 6. Правила написания промптов суб-агентов

**ПРОМПТЫ НЕ ДОЛЖНЫ ДУБЛИРОВАТЬ КОНТЕНТ ИЗ REFERENCES/*.**

Каждый промпт содержит:
- Роль и задачу агента
- Вводные данные (название скилла, путь)
- Ссылки на `references/*` с детальной информацией

Агент **сам читает** referenced файлы по ссылкам из промпта.

### Структура промпта

**Минимальная структура:**
```
Ты -- агент для {роль}.

Задача: {краткое описание задачи}.

## Вводные

Название скилла: {skill-name}
Путь к скиллу: .gigacode/skills/{skill-name}/

## Правила проверки/выполнения

См. [`rules.md`](rules.md) -- раздел {section}.
См. [`workflows.md`](workflows.md) -- раздел {section}.
См. [`templates.md`](templates.md) -- раздел {section}.

## Формат отчёта

См. [`templates.md`](templates.md) -- раздел "Формат отчёта: {report-name}".
```

**НЕЛЬЗЯ:**
- Дублировать шаги проверок из workflows.md
- Дублировать правила из rules.md
- Дублировать форматы отчётов из templates.md
- Включать развёрнутые инструкции, которые уже есть в references/*

**МОЖНО:**
- Кратко описать роль и задачу агента
- Указать вводные данные (название скилла, путь)
- Дать ссылки на соответствующие разделы references/*

## 7. Разделение контента по файлам references/

**Каждый файл `references/*` должен содержать ТОЛЬКО релевантный тип контента.**

Это предотвращает дублирование, упрощает навигацию и обеспечивает консистентность.

| Файл | Тип контента | Примеры содержимого |
|---|---|---|
| `workflows.md` | Пошаговые инструкции, workflow | Детальные шаги аудита/рефакторинга, правила делегирования суб-агентов |
| `rules.md` | Правила, ограничения, критерии | Что оставлять/удалять, кросс-ссылки, правила написания промптов, разделение контента |
| `templates.md` | Шаблоны, форматы, фронтматтер | Форматы отчётов аудита/суб-агентов, правила согласованности фронтматтера |
| `checklists.md` | Чек-листы, контрольные списки | Чек-лист аудита скилла, чек-лист агентного workflow, чек-лист качества отчётов |
| `examples.md` | Примеры до/после, кейсы | Примеры рефакторинга скиллов, good/bad примеры |
| `prompts.md` | Промпты для суб-агентов | Промпты task-агентов для различных проверок и шагов рефакторинга |

**НЕЛЬЗЯ:**
- Размещать workflow-шаги в `templates.md` или `rules.md`
- Размещать примеры в `workflows.md` или `rules.md`
- Размещать шаблоны отчётов в `prompts.md`
- Размещать чек-листы в `templates.md` или `rules.md`
- Размещать правила в `workflows.md` или `prompts.md`

**МОЖНО:**
- Ссылаться на контент из других файлов через `references/{filename}.md`
- Дублировать заголовки секций для контекста (но не сам контент)
