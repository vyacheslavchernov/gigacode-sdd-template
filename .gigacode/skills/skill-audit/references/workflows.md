# Workflows — Skill Audit

Детальные шаги аудита и рефакторинга скиллов.

See [`SKILL.md`](../SKILL.md) — overview and scenarios.

---

## Правила использования суб-агентов

### Когда делегировать суб-агенту

| Шаг аудита | Делегировать? | Причина |
|---|---|---|
| Сборка списка файлов скилла | **Да** | Ёмкий контекст -- нужно прочитать все файлы скилла |
| Измерение размера SKILL.md | **Нет** | Простая команда, не требует контекста |
| Проверка дублирования (внутренняя) | **Да** | Нужно сравнить SKILL.md ↔ references/* |
| Проверка дублирования (внешняя) | **Да** | Нужно сравнить со docs/, guidelines/ |
| Проверка ссылок на docs/guidelines | **Да** | Нужно прочитать целевые файлы и сравнить контент |
| Проверка согласованности | **Да** | Нужно проверить фронтматтер, терминологию, кросс-ссылки |
| Генерация отчёта | **Нет** | Формируется на основе результатов проверок |
| Рефакторинг | **Да** | Декомпозируется на атомарные шаги, каждый -- отдельный агент |

### Параллелизм

- **Проверки** -- запускать **параллельно** (независимые агенты)
- **Изменения (рефакторинг)** -- запускать **последовательно** (зависят друг от друга)

### Формат отчётов суб-агентов

Каждый агент должен вернуть структурированный отчёт по шаблону в [`templates.md`](templates.md).

Промты для суб-агентов -- в [`prompts.md`](prompts.md).

## Workflow аудита

### Шаг 1: Сборка списка файлов скилла (суб-агент)

**Делегируется суб-агенту** -- ёмкий контекст, нужно прочитать все файлы.

1. Запусти суб-агента с промптом из [`prompts.md`](prompts.md) -- "Сборка списка файлов скилла"
2. Получи отчёт в формате File Inventory Report
3. Сохрани отчёт для использования в дальнейших шагах

### Шаг 2: Измерение размера SKILL.md

```bash
wc -l .gigacode/skills/{skill-name}/SKILL.md
```

**Критерий:** <= 200 строк. Если больше -- рефакторить.

### Шаг 3: Проверка дублирования (суб-агенты)

**Запускается параллельно двумя агентами:**

#### 3.1. Внутреннее дублирование (суб-агент)

1. Запусти суб-агента с промптом "Проверка дублирования (внутренняя)"
2. Агент сравнивает SKILL.md ↔ references/* и references/* ↔ references/*
3. Получи отчёт Duplicate Check Report (Internal)

#### 3.2. Внешнее дублирование (суб-агент)

1. Запусти суб-агента с промптом "Проверка дублирования (внешняя)"
2. Агент сравнивает скилл с docs/, guidelines/, GIGACODE.md
3. Получи отчёт Duplicate Check Report (External)

### Шаг 4: Проверка ссылок на docs/guidelines (суб-агент)

1. Запусти суб-агента с промптом "Проверка ссылок на docs/guidelines"
2. Агент проверяет существование всех ссылок и отсутствие дублирования контента
3. Получи отчёт Link Check Report

### Шаг 5: Проверка согласованности (суб-агент)

1. Запусти суб-агента с промптом "Проверка согласованности"
2. Агент проверяет фронтматтер, кросс-ссылки, терминологию, противоречия
3. Получи отчёт Consistency Check Report

### Шаг 5.5: Проверка разделения контента (суб-агент)

**Проверяет, что каждый файл `references/*` содержит только релевантный тип контента.**

1. Запусти суб-агента с промптом "Проверка разделения контента" (см. ниже)
2. Агент проверяет каждый файл references/ согласно правилам из [`rules.md`](rules.md) -- раздел "Разделение контента по файлам"
3. Получи отчёт Content Segregation Report

**Промпт суб-агента:**

```
Ты -- агент для проверки разделения контента по файлам скилла.

Задача: проверить, что каждый файл references/* содержит только релевантный тип контента.

## Вводные

Название скилла: {skill-name}
Путь к скиллу: .gigacode/skills/{skill-name}/

## Правила проверки

См. [`rules.md`](rules.md) -- раздел "Разделение контента по файлам".

Проверь каждый файл references/:
- workflows.md -- содержит только workflow-шаги и инструкции
- rules.md -- содержит только правила, ограничения, критерии
- templates.md -- содержит только шаблоны, форматы, фронтматтер
- checklists.md -- содержит только чек-листы
- examples.md -- содержит только примеры до/после
- prompts.md -- содержит только промпты для суб-агентов

Проверь, что:
- Нет workflow-шагов в templates.md, rules.md, prompts.md
- Нет примеров в workflows.md, rules.md, templates.md
- Нет шаблонов отчётов в prompts.md, checklists.md, workflows.md
- Нет правил в workflows.md, examples.md, prompts.md
- Нет чек-листов в templates.md, examples.md, rules.md

## Формат отчёта

# Content Segregation Report: {skill-name}

- **Нарушений найдено:** {N}

## Issues

  - **Где:** {секция, строки}
  - **Что нарушено:** {правило из rules.md}
  - **Рекомендация:** {куда перенести контент}

## Clean
{если нарушений нет, написать "Нарушений не обнаружено"}
```

### Шаг 6: Генерация отчёта

Объедини результаты всех суб-агентов в итоговый отчёт аудита по шаблону из [`templates.md`](templates.md).

### Шаг 7: Применение рефакторинга (суб-агенты)

**Если пользователь запросил рефакторинг -- примени изменения последовательно:**

1. **Декомпозируй рефакторинг на атомарные шаги** (перенос контента, обновление SKILL.md, добавление кросс-ссылок и т.д.)
2. **Каждый шаг делегируй отдельному суб-агенту** с промптом "Атомарный шаг рефакторинга"
3. **Выполняй шаги последовательно** (зависят друг от друга)
4. После каждого шага получай Refactoring Report

### Шаг 8: Повторный аудит после рефакторинга

**Если был выполнен рефакторинг -- проведи полный аудит заново:**

1. Повтори Шаг 1-8 в полном соответствии с workflow
2. Убедись, что все проблемы исправлены
3. Предоставь итоговый отчёт пользователю

## Проверка дублирования

### SKILL.md ↔ references/*

1. Прочитай SKILL.md и все файлы references/
2. Для каждой секции SKILL.md проверь:
   - Есть ли аналогичный контент в references/?
   - Если да -- SKILL.md должен содержать только ссылку
   - Если нет -- контент должен остаться в SKILL.md (если компактный) или быть перенесён
3. Для каждого файла references/ проверь:
   - Есть ли дублирование контента в другом файле references/?
   - Если да -- объединить

### Ссылки на docs/ и guidelines/

1. Проверь, не дублирует ли SKILL.md или references/ контент из:
   - `guidelines/*.md` -- гайдлайны проекта
   - `docs/architecture.md` -- архитектура
   - `GIGACODE.md` -- структура проекта
2. Если контент есть в guidelines/ -- оставить только ссылку в SKILL.md
3. Пример:
   ```markdown
   Bad: полный текст guidelines/documentation-guidelines.md в SKILL.md
   Good: **ВСЕГДА** следуй [`guidelines/documentation-guidelines.md`](../../guidelines/documentation-guidelines.md)
   ```
