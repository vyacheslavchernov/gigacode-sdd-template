# Skill Audit

Аудит и рефакторинг структуры скиллов -- проверка на дублирование, разделение больших блоков, согласованность файлов.

## Цель

Каждый скилл должен быть компактным (SKILL.md <= 200 строк) и содержать только ссылки на детализированные файлы в `references/`. Детальный контент (workflow, примеры, шаблоны) -- в отдельных файлах.

## Сценарии

### 1. Аудит скилла
```
аудит скилла {skill-name}
```
1. Сборка списка файлов скилла (суб-агент)
2. Запусти суб-агентов для проверок (параллельно):
   - Сборка списка файлов скилла
   - Проверка дублирования (внутренняя + внешняя)
   - Проверка ссылок на docs/guidelines
   - Проверка согласованности
   - Проверка разделения контента
3. Проверь размер SKILL.md (<= 200 строк) -- самостоятельно
4. Объедини результаты суб-агентов в отчёт
5. Предоставь отчёт пользователю

### 2. Рефакторинг скилла
```
рефакторинг скилла {skill-name}
```
1. Проведи аудит (см. сценарий 1)
2. Декомпозируй рефакторинг на атомарные шаги
3. Делегируй каждый шаг отдельному суб-агенту (последовательно)
4. После рефакторинга проведи полный аудит заново
5. Предоставь итоговый отчёт

## Critical Rules

- **ALWAYS** проверяй размер SKILL.md (лимит 200 строк)
- **ALWAYS** проверяй дублирование перед рефакторингом
- **ALWAYS** добавляй кросс-ссылки при рефакторинге
- **ALWAYS** делегируй ёмкие проверки суб-агентам (сборка файлов, дублирование, ссылки, согласованность)
- **ALWAYS** запускай проверки суб-агентов параллельно (независимые)
- **ALWAYS** выполняй шаги рефакторинга последовательно (зависимые)
- **ALWAYS** проводи полный аудит после рефакторинга
- **NEVER** удаляй контент без согласования
- **NEVER** ломай существующие ссылки
- **APPLY** рефакторинг только по запросу пользователя
- **PRESENT** отчёт аудита перед применени
