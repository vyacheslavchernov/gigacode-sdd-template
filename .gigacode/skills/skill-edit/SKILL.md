# Skill Edit

Создание и редактирование скиллов в проекте в соответствии со стандартами SpecDriven.

## Правила проекта

**ОБЯЗАТЕЛЬНО** следуй гайдлайнам:
- [`guidelines/specification-guidelines.md`](../../guidelines/specification-guidelines.md) — структура, ID, правила
- [`guidelines/documentation-guidelines.md`](../../guidelines/documentation-guidelines.md) — структура docs/, фронтматтер
- Скилл-рефакторинг: [`skill-refactor/SKILL.md`](../skill-refactor/SKILL.md) — стандарты структуры скиллов

## Сценарии

### 1. Создание нового скилла

```
создай скилл для {описание назначения}
```

1. Определи название и назначение скилла
2. Задай уточняющие вопросы (см. ниже)
3. Сгенерируй структуру: SKILL.md + references/
4. Проверь уникальность названия
5. Зарегистрируй в GIGACODE.md
6. Вызови `skill-refactor` для аудита нового скилла (суб-агент)
7. Исправь замечания аудита (до 3 итераций)
8. Предоставь результат пользователю

### 2. Редактирование существующего скилла

```
обнови скилл {skill-name} — {описание изменений}
```

1. Найди и прочитай текущий скилл: `.gigacode/skills/{skill-name}/SKILL.md`
2. Определи scope изменений:
   - **Минорные** — исправление описания, триггеров, фронтматтера
   - **Мажорные** — добавление/удаление сценариев, структуры, references/
3. Задай уточняющие вопросы (см. ниже)
4. Внеси изменения в соответствующие файлы
5. Проверь согласованность кросс-ссылок
6. Вызови `skill-refactor` для аудита изменений (суб-агент)
7. Исправь замечания аудита (до 3 итераций)
8. Предоставь результат пользователю

### 3. Рефакторинг скилла

```
рефакторинг скилла {skill-name}
```

1. Запусти `skill-refactor` через суб-агента
2. Получи отчёт о проблемах
3. Исправь замечания (разделение контента, дублирование, кросс-ссылки)
4. Повтори аудит до PASS или 3 итераций
5. Предоставь результат

## Уточняющие вопросы

### Базовые

- **Название скилла** — краткое, в стиле snake_case (например: `skill-audit`, `doc-generator`)
- **Назначение** — что делает скилл, какую задачу решает
- **Триггеры** — какие команды/фразы активируют скилл (на русском и английском)

### Структура

- **Сложность** — простой (только SKILL.md) или продвинутый (SKILL.md + references/)?
- **Ссылки на external** — нужны ли ссылки на guidelines/, docs/, другие скиллы?
- **Шаблоны** — нужны ли встроенные шаблоны для типовых сценариев?

### Редактирование (для существующих скиллов)

- **Scope изменений** — что именно нужно изменить (описание, сценарии, структура, references/)?
- **Совместимость** — влияет ли изменение на другие скиллы (кросс-ссылки)?
- **Версия** — нужна ли пометка версии (semver) во фронтматтере?

### Дополнительный функционал

Предложи пользователю:
- **Регистрация в GIGACODE.md** — автоматическое добавление в список доступных скиллов
- **Кросс-ссылки** — ссылки из других скиллов на новый (если он полезен для них)
- **Тесты скилла** — базовая валидация работы скилла
- **Документация** — создание README.md в каталоге скилла

## Critical Rules

- **ALWAYS** задавай уточняющие вопросы при неясностях
- **ALWAYS** проверяй уникальность названия (для новых скиллов)
- **ALWAYS** регистрируй новый скилл в GIGACODE.md
- **ALWAYS** вызывай skill-refactor для аудита после создания/изменения (суб-агент)
- **ALWAYS** исправляй критические замечания аудита (до 3 итераций)
- **NEVER** создавай скилл с дублирующим названием
- **NEVER** пропускай этап аудита
- **NEVER** ломай существующие кросс-ссылки при редактировании
- **NEVER** додумывай требования — используй NEEDS_CLARIFICATION
