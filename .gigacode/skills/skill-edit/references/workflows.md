# Workflows -- Skill Edit

See [`SKILL.md`](../SKILL.md) -- overview and scenarios.

## Workflow создания скилла

### Шаг 1: Определение scope

1. Получи запрос пользователя на создание скилла
2. Определи:
   - Название скилла (если не указано — предложи варианты)
   - Назначение (краткое описание)
   - Триггеры (команды для активации)
3. **Если что-то неясно — ЗАДАЙ УТОЧНЯЮЩИЕ ВОПРОСЫ**

### Шаг 2: Уточнение структуры

Задай вопросы:
1. **Простой или продвинутый?**
   - Простой: только SKILL.md (<= 200 строк, без references/)
   - Продвинутый: SKILL.md + references/ с детализацией

2. **Нужны ли ссылки на external ресурсы?**
   - guidelines/ проекта
   - docs/
   - другие скиллы

3. **Нужны ли шаблоны?**
   - Встроенные шаблоны для типовых сценариев
   - Примеры good/bad

### Шаг 3: Предложение дополнительного функционала

Предложи пользователю:
- **Регистрация в GIGACODE.md** — автоматическое добавление в список `## Доступные скиллы`
- **Кросс-ссылки из других скиллов** — если новый скилл полезен для существующих
- **Тесты скилла** — базовая валидация (чек-лист выполнения)
- **README.md** — краткая документация в каталоге скилла

### Шаг 4: Проверка уникальности

```bash
# Проверить, нет ли уже скилла с таким названием
ls .gigacode/skills/
```

**Если название занято:**
- Предложи альтернативу (например, добавить префикс/суффикс)
- Не создавай скилл с дублирующим названием

### Шаг 5: Генерация структуры

Создай файлы:

```
.gigacode/skills/{skill-name}/
├── SKILL.md              # Обязательный (<= 200 строк)
└── references/           # Опционально
    ├── workflows.md      # Детальные шаги
    ├── examples.md       # Примеры
    ├── templates.md      # Шаблоны
    ├── checklists.md     # Чек-листы
    └── prompts.md        # Промпты (опционально)
```

**Правила наполнения:**
- SKILL.md: фронтматтер + ёмкое описание + сценарии + отдельные секции для каждого типа контента
- Каждая секция в SKILL.md ссылается на существующий файл в `references/`
- Если файл `references/*` не нужен — секцию не создавай
- references/workflows.md: подробные шаги workflow
- references/examples.md: примеры использования
- references/templates.md: YAML-фронтматтеры, форматы файлов
- references/checklists.md: чек-листы завершения
- references/prompts.md: промпты для агентов (опционально)

### Шаг 6: Генерация контента

Используй шаблоны из [`references/templates.md`](templates.md):

1. Заполни фронтматтер:
   ```yaml
   ---
   name: {skill-name}
   last_updated: {YYYY-MM-DD}
   scope: skill  # или skill-reference
   description: {краткое описание}
   ---
   ```

2. Наполни SKILL.md:
   - Название и описание
   - Правила проекта (ссылки на guidelines/)
   - Сценарии использования
   - Уточняющие вопросы
   - Workflow (ссылки на references/)
   - Критические правила (ALWAYS/NEVER)

3. При наличии references/ — наполни детализацией

### Шаг 7: Регистрация в GIGACODE.md

Открой `GIGACODE.md`, найди секцию `## Доступные скиллы`, добавь:

```markdown
| `{skill-name}` | {краткое описание назначения} |
```

**Правила:**
- Добавляй в алфавитном порядке
- Описание — максимум 1 строка
- Формат: таблица с именами скиллов и описанием

### Шаг 8: Аудит через skill-refactor

**ИСПОЛЬЗУЙ СУБ-АГЕНТА:**

```
task(description="Audit skill: {skill-name}", prompt="Используй скилл skill-refactor для аудита нового скилла {skill-name} в .gigacode/skills/{skill-name}/. Выполни полную проверку: размер SKILL.md, дублирование, согласованность ссылок, кросс-ссылки. Сфокусируйся на качестве структуры скилла.", subagent_type="general")
```

### Шаг 9: Цикл автофиксов

Получи результат аудита:

| Статус | Действие |
|---|---|
| **PASS** | Перейти к Шагу 10 |
| **WARN** | Исправь замечания → повтори аудит (Шаг 8) |
| **FAIL** | Исправь замечания → повтори аудит (Шаг 8) |

**Логика:**
```
max_iterations = 3
iteration = 0
audit_status = {результат Шага 8}

while audit_status in [WARN, FAIL] and iteration < max_iterations:
    iteration += 1
    исправь_замечания(результат_аудита)
    аудит = запустить_skill_refactor({skill-name})
    audit_status = аудит.status

if audit_status != PASS:
    предупредить_пользователя(f"Остались замечания после {iteration} итераций")
```

### Шаг 10: Предоставление результата

Предоставь пользователю:

1. **Структуру скилла** — список созданных файлов
2. **Результат аудита** — статус и summary
3. **Список итераций** — сколько раз пришлось исправлять
4. **Оставшиеся замечания** — если есть (после 3 итераций)
5. **Рекомендации** — что можно улучшить

## Workflow редактирования существующего скилла

### Шаг 1: Загрузка текущего состояния

1. Определи название скилла (`{skill-name}`)
2. Прочитай `SKILL.md`: `.gigacode/skills/{skill-name}/SKILL.md`
3. Прочитай все файлы `references/` (если есть)
4. Проверь регистрацию в `GIGACODE.md`

### Шаг 2: Определение scope изменений

Классифицируй изменения:

| Тип | Примеры | Требования |
|---|---|---|
| **Минорные** | исправление опечаток, обновление описания, добавление триггеров | Без аудита (или быстрый аудит) |
| **Мажорные** | добавление сценариев, изменение структуры, добавление/удаление references/ | Обязательный аудит через skill-refactor |

### Шаг 3: Уточнение у пользователя

Задай вопросы:
1. **Что именно меняется?** — конкретные файлы, секции, сценарии
2. **Влияет ли на другие скиллы?** — проверка кросс-ссылок
3. **Нужно ли обновлять GIGACODE.md?** — если изменилось описание/назначение

### Шаг 4: Внесение изменений

1. Обнови соответствующие файлы:
   - `SKILL.md` — основные изменения
   - `references/workflows.md` — если изменился workflow
   - `references/templates.md` — если изменились шаблоны
   - `references/examples.md` — если изменились примеры
   - `references/checklists.md` — если изменились чек-листы
2. Проверь согласованность кросс-ссылок
3. Обнови `last_updated` во фронтматтере

### Шаг 5: Проверка согласованности

- [ ] SKILL.md <= 200 строк
- [ ] Все ссылки на `references/` ведут на существующие файлы
- [ ] Все файлы `references/` ссылаются на `SKILL.md`
- [ ] Нет дублирования контента
- [ ] `last_updated` актуален
- [ ] Если мажорные изменения — готовимся к аудиту

### Шаг 6: Аудит (для мажорных изменений)

**ИСПОЛЬЗУЙ СУБ-АГЕНТА:**

```
task(description="Audit skill edit: {skill-name}", prompt="Используй скилл skill-refactor для аудита изменений в скилле {skill-name} в .gigacode/skills/{skill-name}/. Проверь согласованность обновлённых файлов, кросс-ссылки, отсутствие дублирования. Сфокусируйся на том, что изменения не сломали существующую структуру.", subagent_type="general")
```

### Шаг 7: Цикл автофиксов

Аналогично шагу создания — исправь замечания до PASS или 3 итераций.

### Шаг 8: Предоставление результата

Предоставь пользователю:
1. **Список изменённых файлов**
2. **Результат аудита** — статус и summary
3. **Список итераций** — сколько раз пришлось исправлять
4. **Рекомендации** — что можно улучшить

## Workflow рефакторинга скилла

### Шаг 1: Запуск аудита

```
task(description="Refactor skill: {skill-name}", prompt="Используй скилл skill-refactor для полного аудита и рефакторинга скилла {skill-name} в .gigacode/skills/{skill-name}/. Проверь: размер SKILL.md, дублирование, согласованность ссылок, кросс-ссылки. При необходимости раздели контент на файлы references/.", subagent_type="general")
```

### Шаг 2: Применение рекомендаций

Получи отчёт от skill-refactor:

| Проблема | Решение |
|---|---|
| SKILL.md > 200 строк | Перенеси контент в references/ |
| Дублирование | Удали дубликаты, оставь ссылки |
| Ломаются кросс-ссылки | Обнови все ссылки |
| Нет согласованности | Приведи к единому стилю |

### Шаг 3: Повторный аудит

Повтори Шаг 1 до PASS или 3 итераций.

### Шаг 4: Предоставление результата

1. **Список изменений** — что было изменено
2. **Результат аудита** — статус и summary
3. **Список итераций**

## Предложение дополнительного функционала

Всегда предлагай:

1. **Кросс-ссылки**
   - Проверь, используются ли существующие скиллы новый функционал
   - Если да — добавь ссылки из тех скиллов на новый

2. **Тесты скилла**
   - Чек-лист: выполнить каждый сценарий скилла
   - Проверка: все ссылки рабочи, фронтматтер консистентен

3. **Документация**
   - README.md с кратким описанием
   - Примеры использования в docs/skills/
