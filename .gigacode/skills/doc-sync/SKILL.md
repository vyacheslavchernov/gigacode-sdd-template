# Doc Sync

Обновление документации проекта в соответствии с текущим состоянием кода.

## Что обновляет

1. **`docs/modules/*.md`** — документация модулей
2. **`docs/packages/*/README.md`** — документация пакетов
3. **`docs/architecture.md`** — архитектура, паттерны
4. **`docs/README.md`** — навигация
5. **`README.md`** в корнях модулей — пользовательская документация
6. **`docs/testing/*.md`** — если изменились тесты
7. **`GIGACODE.md`** — если изменилась структура каталогов, гайдлайны, скиллы или команды
8. **`specs/**/*.md`** — если изменилось поведение системы, описанное в спецификациях
9. **`docs/**`** - любое другое содержимое документации затронутое изменениями в коде

## Обязательный чек-лист (ВСЕГДА проходить перед завершением)

**Перед сообщением пользователю о завершении doc-sync проверь каждый пункт и отметь:**

```
Документация обновлена:
- [ ] docs/modules/{изменённый_модуль}.md
- [ ] docs/packages/{изменённый_пакет}/*.md
- [ ] README.md в корне каждого изменённого модуля
- [ ] docs/architecture.md (если изменилась структура/зависимости/нужно отразить новые архитектурные решения)
- [ ] docs/README.md (если изменилась навигация/структура)
- [ ] docs/testing/*.md (если изменились тесты)
- [ ] specs/{domain}/{spec-id}-spec.md (если изменилось поведение системы, описанное в спецификациях)
- [ ] GIGACODE.md (если изменилась структура каталогов, гайдлайны, скиллы или команды)
```

**Если хотя бы один пункт не отмечен — не завершай doc-sync.**

## Правила работы

**ВСЕГДА** следуй правилам проекта:
- [`guidelines/documentation-guidelines.md`](../../guidelines/documentation-guidelines.md) — структура, фронтматтер, стиль
- [`guidelines/gigacode-md-guidelines.md`](../../guidelines/gigacode-md-guidelines.md) — правила обновления GIGACODE.md

**Лимиты:** один файл ≤ 200 строк, фронтматтер с `last_updated` и `scope`. GIGACODE.md ≤ 40 строк.

## Обновление GIGACODE.md

GIGACODE.md обновляется **только** при изменении структуры проекта:

| Триггер | Действие |
|---|---|
| Новый/удалённый каталог | Добавить/удалить строку в таблице каталогов |
| Новый гайдлайн | Добавить строку в таблицу каталогов |
| Новый скилл | Добавить строку в таблицу скиллов |
| Изменение назначения каталога/скилла | Обновить описание |

**Правила:**
- Не удаляй существующие секции
- Не добавляй детали реализации
- Не превыси 40 строк (таблица каталогов + скиллы)
- Обнови `last_updated` во фронтматтере

## Сценарии

### 1. Обновление по diff

```bash
git diff HEAD
# или
git diff main...{branch}
```

1. Проанализируй diff → определи затронутые модули
2. Запусти `Explore`-агентов для изменённых пакетов
3. Обнови документацию → проверь кросс-ссылки

### 2. Обновление по ветке

```bash
git diff main...{branch} --stat
```

1. Определи масштаб → запусти `Explore`-агентов **параллельно** для каждого модуля
2. Сравни документацию с фактическим кодом
3. Обнови `docs/architecture.md`, `docs/README.md` и `GIGACODE.md` (если изменилась структура)

### 3. Обновление модуля

```
обнови документацию для модуля {название}
```

1. Определи путь модуля → запусти `Explore`-агента
2. Обнови: `docs/modules/{module}.md`, `README.md`, `docs/packages/`

### 4. Полное обновление

1. Параллельные `Explore`-агенты для всех модулей
2. Проверь структуру `docs/packages/` на соответствие коду
3. Проверь `docs/architecture.md`, `docs/README.md` и `GIGACODE.md`

## Workflow

### Шаг 1: Исследование

**ВСЕГДА** используй `Explore`-агентов. Промпт:

```
Исследуй пакет {package-path}. Собери:
1. Публичные классы/интерфейсы/enum/record/модули (в зависимости от языка)
2. Назначение каждого (1 предложение), ключевые методы/функции
3. Зависимости от других классов
4. Декораторы/аннотации (только если влияют на поведение)
5. Фреймворк автоконфигурация (если есть)
```

### Шаг 2: Сравнение

Сравни результаты с текущей документацией:
- Добавлено/удалено публичных сущностей?
- Изменились сигнатуры?
- Изменились зависимости?
- Изменилась структура каталогов, гайдлайны или скиллы? → обновить `GIGACODE.md`

### Шаг 3: Обновление

1. Прочитай текущую версию файла
2. Внеси минимальные изменения
3. Обнови `last_updated`
4. Проверь кросс-ссылки
5. Если изменилась структура проекта — обнови `GIGACODE.md`

### Шаг 4: Проверка

Запусти `Explore`-агента для проверки полноты.
