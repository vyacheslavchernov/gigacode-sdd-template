# Workflows — Doc Sync

Детальный workflow обновления документации.

See [`SKILL.md`](../SKILL.md) -- overview and scenarios.

---

## Шаг 1: Исследование

**ВСЕГДА** используй `Explore`-агентов. Промпт:

```
Исследуй пакет {package-path}. Собери:
1. Публичные классы/интерфейсы/enum/record/модули (в зависимости от языка)
2. Назначение каждого (1 предложение), ключевые методы/функции
3. Зависимости от других классов
4. Декораторы/аннотации (только если влияют на поведение)
5. Фреймворк автоконфигурация (если есть)
```

## Шаг 2: Сравнение

Сравни результаты с текущей документацией:
- Добавлено/удалено публичных сущностей?
- Изменились сигнатуры?
- Изменились зависимости?
- Изменилась структура каталогов, гайдлайны или скиллы? → обновить `GIGACODE.md`

## Шаг 3: Обновление

1. Прочитай текущую версию файла
2. Внеси минимальные изменения
3. Обнови `last_updated`
4. Проверь кросс-ссылки
5. Если изменилась структура проекта — обнови `GIGACODE.md`

## Шаг 4: Проверка

Запусти `Explore`-агента для проверки полноты.

---

## Обновление GIGACODE.md

GIGACODE.md обновляется **только** при изменении структуры проекта:

| Триггер | Действие |
|---|---|
| Новый/удалённый каталог | Добавить/удалить строку в таблице каталогов |
| Новый гайдлайн | Добавить строку в таблицу каталогов |
| Новый скилл | Добавить строку в таблицу скиллов |
| Изменение назначения каталога/скилла | Обновить описание |

**Правила:**
- Не удаляй существующие секции
- Не добавляй детали реализации
- Не превыси 40 строк (таблица каталогов + скиллы)
- Обнови `last_updated` во фронтматтере

> **Подробности:** [`guidelines/gigacode-md-guidelines.md`](../../guidelines/gigacode-md-guidelines.md) §3
