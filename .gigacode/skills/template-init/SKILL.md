# Template Init

Интерактивная инициализация нового проекта на базе SpecDriven-шаблона.

## Сценарий

```
инициализируй проект для {описание}
```

1. Задай уточняющие вопросы (см. ниже)
2. Инициализируй структуру проекта
3. Сформируй гайдлайны
4. Подготовь проект к работе (установи зависимости, собери, запусти тесты)
5. Обновите README.md и GIGACODE.md
6. Предоставь результат пользователю

## Уточняющие вопросы

Задай вопросы **последовательно**, по одному. Жди ответа перед следующим вопросом.

### Вопрос 1: Название проекта

```
Как называется проект?
```

- Ожидаемый формат: kebab-case или camelCase (например: `webfetch`, `my-api-service`)
- Если не указано — предложи сгенерировать на основе описания

### Вопрос 2: Назначение проекта

```
Кратко опиши назначение проекта — что он делает и какую проблему решает?

- 1-2 предложения
- Описывай ценность, а не технологии
```

### Вопрос 3: Язык программирования

```
На каком языке будет писаться проект?
```

Предложи варианты:

| Язык | Версия |
|---|---|
| TypeScript/Node.js | 20+ (LTS) |
| Python | 3.12+ |
| Java | 21+ (LTS) |
| Rust | 1.75+ |
| Go | 1.22+ |
| C++ | 23 (C++23) |
| C# | 12+ / .NET 8+ (LTS) |

Пользователь может предложить и свой вариант.

### Вопрос 4: Инструменты сборки

На основе выбранного языка предложи подходящие инструменты:

**TypeScript/Node.js:**
- Сборка: `npm` (Recommended), `yarn`, `pnpm`
- Тесты: `vitest` (Recommended), `jest`
- Форматирование: `prettier` + `eslint`
- HTTP-фреймворк (если web): `express`, `fastify`, `hono`

**Python:**
- Сборка: `uv` (Recommended), `pip`, `poetry`, `pdm`
- Тесты: `pytest` (Recommended)
- Форматирование: `ruff` (Recommended), `black`
- HTTP-фреймворк (если web): `fastapi` (Recommended), `flask`

**Java:**
- Сборка: `Maven` (Recommended), `Gradle`
- Тесты: `JUnit 5` + `Mockito`
- Форматирование: `spotless`
- Фреймворк (если web): `Spring Boot` (Recommended)

**Rust:**
- Сборка: `Cargo` (встроен)
- Тесты: `cargo test` (встроен)
- Форматирование: `rustfmt` + `clippy`

**Go:**
- Сборка: `go mod` (встроен)
- Тесты: `go test` (встроен)
- Форматирование: `gofmt` (встроен)
- HTTP-фреймворк (если web): стандартная библиотека (Recommended)

**C++**
- Сборка: CMake (Recommended), Ninja, MSBuild (для Visual Studio)
- Тесты: Google Test (Recommended), Catch2, doctest
- Форматирование: clang-format + clang-tidy

**C#**
- Сборка: MSBuild (встроен в .NET SDK), dotnet build (Recommended), NUKE (для сложных сценариев)
- Тесты: xUnit (Recommended), NUnit, MSTest
- Форматирование: .editorconfig + dotnet format (Recommended), StyleCop.Analyzers

Если пользователь указал собственный вариант языка для проекта, то собери список рекомендованных инструметов для этого языка. Список должен быть аналогичным тем, что представлены выше.

### Вопрос 5: Тип интерфейса

```
Какой интерфейс будет у проекта?
```

Предложи варианты:

| Тип | Описание |
|---|---|
| **CLI** (Recommended) | Командная строка, терминал |
| **GUI** | Графический интерфейс, десктоп или веб |
| **API-only** | Только HTTP API, без UI |

На основе выбора предложи типовые решения:

**CLI:**
- TypeScript/Node.js: `ink` (React in terminal, Recommended), `commander`, `clack`
- Python: `rich` (Recommended), `click`, `typer`, `textual` (для rich-TUI)
- Java: `clap4j`, `prompt4j`
- Rust: `clap` + `indicatif` (Recommended), `ratatui` (для TUI)
- Go: `cobra`, `bubbletea` (для TUI, Recommended)

**GUI — Web (TypeScript/Node.js):**
- Фреймворк: `Next.js` (Recommended), `Vite + React`
- UI-кит: `shadcn/ui` + `Tailwind CSS` (Recommended), `MUI`, `Chakra UI`
- Стиль: минималистичный, современный, чистый

**GUI — Web (Python):**
- Фреймворк: `Streamlit` (Recommended для data-приложений), `FastAPI + HTMX`, `Gradio`
- Альтернатива: `Reflex` (Python-native GUI)

**GUI — Desktop (TypeScript/Node.js):**
- `Tauri` (Recommended, Rust backend + web frontend)
- `Electron` (тяжёлый, но мощный)

**GUI — Desktop (Python):**
- `PyQt6` / `PySide6` (Recommended)
- `CustomTkinter` (лёгкий)
- `Flet` (Flutter для Python)

**GUI — Desktop (Java):**
- `JavaFX` (Recommended)
- `Swing` (legacy)

**API-only:**
- Просто HTTP-сервер без UI-слоя

Если пользователь указал собственный вариант языка для проекта, то собери список типовых решений инструметов для этого языка с учётом выбранных инструментов. Список должен быть аналогичным тем, что представлены выше.

```json
  }

```

### Шаг 2: Проверка установленных инструментов

Проверь доступность ключевых инструментов:

```bash
# TypeScript
node --version && npm --version

# Python
python --version && uv --version || pip --version

# Java
java --version && mvn --version || gradle --version

# Rust
rustc --version && cargo --version

# Go
go version
```

**Если инструмент не установлен:**
1. Сообщи пользователю
2. Предложи инструкцию по установке
3. Предложи продолжить без него (с предупреждением) или отменить

### Шаг 3: Инициализация структуры проекта

**ВАЖНО:** Проект инициализируется **напрямую в текущем рабочем каталоге**. Не создавай отдельную поддиректорию с именем проекта (`project-name/`). Вся структура проекта разворачивается в корне.

Создай структуру на основе выбранного стека:

#### TypeScript/Node.js (npm + vitest)

```
├── src/
│   ├── index.ts
│   └── ...
├── tests/
│   ├── unit/
│   └── integration/
├── package.json
├── tsconfig.json
├── vitest.config.ts
├── .eslintrc.json
├── .prettierrc
└── .gitignore
```

#### Python (uv + pytest)

```
├── src/
│   └── {package_name}/
│       ├── __init__.py
│       └── ...
├── tests/
│   ├── unit/
│   └── integration/
├── pyproject.toml
├── .ruff.toml
└── .gitignore
```

#### Java (Maven + JUnit 5)

```
├── src/
│   ├── main/
│   │   └── java/
│   └── test/
│       └── java/
├── pom.xml
└── .gitignore
```

#### Rust (Cargo)

```
├── src/
│   └── lib.rs
│   └── main.rs (если binary)
├── tests/
├── Cargo.toml
└── .gitignore
```

#### Go (go mod)

```
├── pkg/
├── internal/
├── cmd/
├── tests/
├── go.mod
├── go.sum
└── .gitignore
```

#### CLI (ink / rich / clap / cobra)

```
├── src/
│   ├── index.{ext}
│   ├── cli.{ext}          # настройка CLI-фреймворка
│   └── commands/
│       └── ...
├── tests/
│   ├── unit/
│   └── integration/
├── package.json / pyproject.toml / ...
└── .gitignore
```

#### GUI — Web (Next.js / Streamlit / Tauri)

```
├── src/
│   ├── components/
│   │   ├── ui/             # переиспользуемые UI-компоненты
│   │   └── ...
│   ├── pages/ или app/     # Next.js App Router
│   └── styles/
│       └── globals.css
├── public/
├── tests/
│   ├── unit/
│   └── e2e/
├── package.json / pyproject.toml / ...
└── .gitignore
```

#### GUI — Desktop (PyQt6 / JavaFX / Tauri)

```
├── src/
│   ├── main/
│   │   └── ui/
│   │       ├── main_window.{ext}
│   │       └── components/
│   └── resources/          # иконки, стили
├── tests/
│   ├── unit/
│   └── integration/
└── ...
```

#### API-only

```
├── src/
│   ├── api/
│   │   ├── routes/
│   │   └── middleware/
│   └── index.{ext}
├── tests/
│   ├── unit/
│   └── integration/
└── ...
```

**Правила:**
- Создай минимальный "hello, world" файл в `src/` — простейший код, выводящий `"hello, world"`
- Создай минимальный тестовый файл — тест, который проверяет вывод `"hello, world"`
- НЕ генерируй реальные компоненты приложения (ни UI, ни CLI-команды, ни API-роуты)
- Цель — только убедиться, что проект собирается, запускается и проходит тесты
- `.gitignore` — шаблонный (из существующего), потом расширим под стек

#### `guidelines/ui-style-guidelines.md`

Создаётся **только если** `interfaceType` — `cli` или `gui`. Для `api-only` — пропускается.

```yaml
---
last_updated: YYYY-MM-DD
scope: guidelines
---

# UI Style Guidelines — {project-name}

## Назначение

Этот гайдлайн описывает принципы UI/UX-дизайна для проекта {project-name}.
Все экраны, компоненты и CLI-вывод должны следовать этим правилам для единообразия.

---

## Общие принципы

1. **Минимализм** — ничего лишнего. Каждый элемент должен решать задачу пользователя.
2. **Единообразие** — одинаковые элементы выглядят одинаково во всём приложении.
3. **Доступность** — контраст, размеры, навигация с клавиатуры.
4. **Ясность** — пользователь всегда понимает, что делает и что будет дальше.

---

## {GUI / CLI} — Цветовая палитра

### Основные цвета

| Роль | Цвет | Использование |
|---|---|---|
| Primary | `{hex}` | Кнопки действий, акценты, ссылки |
| Secondary | `{hex}` | Второстепенные элементы, бордеры |
| Background | `{hex}` | Фон страниц/окон |
| Surface | `{hex}` | Карточки, панели, модальные окна |
| Text primary | `{hex}` | Основной текст |
| Text secondary | `{hex}` | Подсказки, описания, disabled |

### Цвета состояний

| Состояние | Цвет | Использование |
|---|---|---|
| Success | `{hex}` | Успешные операции, подтверждение |
| Warning | `{hex}` | Предупреждения, требует внимания |
| Error | `{hex}` | Ошибки, критические уведомления |
| Info | `{hex}` | Информационные сообщения |

**Правила:**
- Никогда не используй цвет как единственный способ передачи информации — дублируй икономкой или текстом
- Контраст текста к фону — минимум WCAG AA (4.5:1 для обычного текста)
- Тёмная тема — зеркально инвертируй background/surface, сохрани primary/accent

## {GUI / CLI} — Компоненты

### Кнопки

| Тип | Стиль | Когда использовать |
|---|---|---|
| Primary | filled, primary color | Главное действие на странице |
| Secondary | outlined, secondary border | Второстепенное действие |
| Text | text-only, no background | Меню, отмена, ссылки |
| Destructive | filled, error color | Удаление, отмена действий |

**Правила кнопок:**
- Минимальая ширина — 80px (desktop) / 44px (mobile touch target)
- Padding — 10px 20px (desktop) / 12px 24px (mobile)
- Border radius — 6px (desktop) / 8px (mobile)
- Hover-состояние — затемнение на 10%

### Формы

- Label сверху, не слева
- Placeholder — подсказка, не замена label
- Валидация — inline, сразу после ввода (не после сабмита)
- Error message — под полем, красным текстом + иконка

### Навигация

- Хлебные крошки для вложенности > 2 уровней
- Sidebar для > 5 разделов
- Top nav для ≤ 5 разделов

---

## {GUI / CLI} — Отступы и сетка

### Система отступов

Используй кратную 4px сетку: `4, 8, 12, 16, 24, 32, 48, 64`

| Контекст | Padding | Gap |
|---|---|---|
| Карточка | 16px | 12px |
| Модальное окно | 24px | 16px |
| Форма (между полями) | — | 16px |
| Секция страницы | — | 32px |

### Адаптивность

| Breakpoint | Ширина | Поведение |
|---|---|---|
| Mobile | < 640px | Одна колонка, full-width элементы |
| Tablet | 640–1024px | Две колонки, компактные карточки |
| Desktop | > 1024px | Три колонки, sidebar |

## {CLI} — Вывод в терминал

### Цвета и стили

Используй палитру терминала (256-color):

| Роль | ANSI / Библиотека |
|---|---|
| Primary | `Style(color=Color.CYAN)` |
| Success | `Style(color=Color.GREEN)` |
| Warning | `Style(color=Color.YELLOW)` |
| Error | `Style(color=Color.RED)` |
| Muted | `Style(color=Color.DIM)` |

### Структура вывода


[заголовок]           # Жирный, Cyan, с иконкой
────────────────────  # Разделитель
[текст]               # Обычный, белый
  ↳ подпункт          # Отступ 2 пробела, Dim
[успех] ✓             # Green, с галочкой
[ошибка] ✗            # Red, с крестиком


### Прогресс и загрузка

- Spinners для операций < 5 секунд
- Progress bar для операций > 5 секунд
- Никакого `print("...")` без статуса

### Таблицы в CLI

- Выравнивание по колонкам
- Заголовок — жирный, разделитель — `─`
- Максимум 3-5 колонок, остальное — в детальный вывод

## {GUI / CLI} — Иконки
```

### Шаг 4.5: Подготовка проекта к работе

**Проект должен быть готов к написанию спецификаций.** После создания структуры и гайдлайнов необходимо убедиться, что проект собирается, запускается и проходит тесты.

#### 1. Установка зависимостей

Выполни команду установки зависимостей для выбранного стека:

```bash
# TypeScript/Node.js
npm install

# Python (uv)
uv sync

# Python (pip)
pip install -r requirements.txt

# Python (poetry)
poetry install

# Python (pdm)
pdm install

# Java (Maven)
mvn compile

# Java (Gradle)
gradle build -x test

# Rust
cargo build

# Go
go mod download
```

**Если установка завершилась ошибкой:**
1. Сообщи пользователю об ошибке
2. Предложи решение (проверить `package.json`/`pyproject.toml`/`pom.xml` и т.д.)
3. Предложи продолжить с предупреждением или отменить

#### 1.5. Проверка и обновление зависимостей

После установки проверь вывод на предупреждения об устаревании, уязвимостях и deprecated-пакетах:

```bash
# TypeScript/Node.js
npm audit
npm outdated

# Python (pip)
pip list --outdated
pip-audit  # если установлен

# Java (Maven)
mvn versions:display-dependency-updates
mvn versions:display-plugin-updates

# Rust
cargo outdated

# Go
go list -m -u all
```

**Если найдены предупреждения:**

1. **Уязвимости (`npm audit`, `pip-audit`)** — критично. Предложи обновить:
   ```bash
   npm audit fix
   pip install --upgrade vulnerable-package
   ```
    Если `audit fix` меняет Major-версии — спроси пользователя перед применением.

2. **Устаревшие зависимости (`npm outdated`, `cargo outdated`, `go list -m -u all`)** — предложи обновить до последней совместимой версии:
   ```bash
   npm update
   cargo update
   go get -u ./...
   ```

3. **Deprecated-пакеты** — если пакет помечен как deprecated, предложи замену:
   - `moment` → `date-fns` или `dayjs`
   - `request` → `node-fetch` или `axios`
   - `uuid@v3` → `uuid@v9+`
   - И другие известные замены для выбранного стека

4. После обновления — **повтори установку и сборку**, чтобы убедиться, что ничего не сломалось.

**Если предупреждений нет** — переходи к шагу «Сборка проекта».

#### 2. Сборка проекта

Выполни команду сборки:

```bash
# TypeScript/Node.js
npm run build

# Python (uv) — проверка типов
uv run mypy src || uv run ruff check src

# Java (Maven)
mvn compile

# Java (Gradle)
gradle compileJava

# Rust
cargo build

# Go
go build ./...
```

**Если сборка завершилась ошибкой:**
1. Сообщи пользователю об ошибке
2. Покажи вывод с ошибкой
3. Предложи исправить или продолжить с предупреждением

**Если сборка прошла, но в выводе есть предупреждения** (deprecated API, устаревшие опции компилятора, устаревшие зависимости):
1. Проанализируй предупреждения — это ошибки или просто warning?
2. Если warning от зависимостей — см. шаг 1.5 (обновить зависимости)
3. Если warning от компилятора/фреймворка — исправь или добавь в `coding-guidelines.md` как известное ограничение

#### 3. Запуск приложения (опционально, для web/API)

Для проектов с серверной частью запусти dev-сервер и убедись, что он стартует:

```bash
# TypeScript (fastify/express)
npm run dev

# Python (fastapi)
uv run uvicorn src.main:app --reload
```

Проверь, что сервер запустился без ошибок (посмотри логи, не упал ли сразу).
После проверки останови сервер.

**Необязательно** для CLI-библиотек и утилит.

#### 4. Запуск тестов

Выполни все тесты:

```bash
# TypeScript/Node.js
npm run test

# Python (pytest)
uv run pytest

# Java (Maven)
mvn test

# Java (Gradle)
gradle test

# Rust
cargo test

# Go
go test ./...
```

**Если тесты прошли** — проект готов к работе.
**Если тесты упали:**
1. Сообщи пользователю (покажи краткий вывод)
2. Если это заглушки — пропусти и предупреди
3. Если реальные тесты упали — предложи исправить или продолжить с предупреждением

#### Итог шага

Проект считается **готовым к работе** только если:
- [x] Зависимости установлены без ошибок
- [x] Нет критических уязвимостей (`npm audit`, `pip-audit` — clean)
- [x] Устаревшие зависимости обновлены или заменены на актуальные аналоги
- [x] Сборка проходит (без критических warning)
- [x] Тесты проходят (или это заглушки)
- [x] (Опционально) Приложение запускается

## Правила

- **Задавай вопросы последовательно**, по одному
- **Не додумывай** — если пользователь не ответил на вопрос, спроси повторно или предложи вариант по умолчанию
- **Проверяй установленные инструменты** перед инициализацией
- **Предлагай инструкции по установке** если инструмент отсутствует
- **Подставляй реальные значения** в гайдлайны — не оставляй placeholder'ов
- **Проект должен быть готов к работе** — зависимости установлены, сборка прошла, тесты прошли (простой "hello, world" + тест)
- **НЕ генерируй реальный код приложения** — только минимальную заглушку для проверки сборки
- **Не создавай поддиректорию с именем проекта** — вся структура разворачивается **напрямую в текущем рабочем каталоге** (корне)
- **Не ломай** существующую структуру SpecDriven-шаблона
- **Сохраняй** `specs/`, `docs/`, `.gigacode/` без изменений
