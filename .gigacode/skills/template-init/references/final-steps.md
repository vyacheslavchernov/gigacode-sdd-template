# Финальные шаги

Шаги 5–8: обновление README.md, GIGACODE.md, .gitignore и предоставление результата.

---

## Шаг 5: Обновление README.md

Прочитай текущий `README.md`. Замени его на проект-специфичную версию:

```yaml
---
last_updated: YYYY-MM-DD
scope: project
---

# {project-name}

{purpose — 1-2 предложения, ценность, а не технологии}

## Установка

{install-command}

## Сборка и запуск

{build-command}
{run-command}

## Использование

# пример команды CLI
{usage-command}

// пример кода
{usage-code}

## Документация

Полная документация проекта: [`docs/README.md`](docs/README.md)
```

**Правила:**
- README содержит только четыре блока: **название**, **назначение**, **сборка/развёртка/установка**, **использование**
- Укажи реальные команды установки, сборки, запуска
- Добавь минимальный пример использования (код или команда)
- Включи ссылки на документацию и гайдлайны
- Не включай: структуру проекта, таблицу команд, SpecDriven workflow, длинные описания — это в `docs/README.md` и `GIGACODE.md`
- Не превысь 30 строк

## Шаг 6: Обновление GIGACODE.md

Прочитай текущий `GIGACODE.md`. Обнови:

1. **Название** — замени шаблонное на реальное
2. **Описание** — сгенерируй 1-2 предложения на основе purpose
3. **Таблица каталогов** — добавь новые гайдлайны:

| Каталог | Назначение |
|---|---|
| `guidelines/build-run-tests-guidelines.md` | Команды сборки, запуска, тестирования |
| `guidelines/coding-guidelines.md` | Правила написания кода для {language} |
| {если gui или cli: `guidelines/ui-style-guidelines.md` | Принципы UI/UX-дизайна для {cli\|gui} |}

4. **Фронтматтер** — обнови `last_updated`

**Правила:**
- Не превысь 40 строк (секция каталогов + скиллы)
- Не удаляй существующие секции
- Не добавляй детали реализации

Детальные правила обновления `GIGACODE.md` — в [`guidelines/gigacode-md-guidelines.md`](../../guidelines/gigacode-md-guidelines.md).

## Шаг 7: Обновление .gitignore

Если проект требует специфичных игнорируемых файлов (node_modules, .venv, target/, .idea/, etc.) — добавь их в `.gitignore`.

```

- Интерфейс: {cli|gui|api-only}
{если gui: - GUI-фреймворк: {guiFramework}}
{если cli: - CLI-фреймворк: {cliFramework}}
- Сборка: {buildTool}
- Тесты: {testFramework}
- Форматирование: {formatting}
- CI/CD: {да/нет}
- Docker: {да/нет}

### Созданные файлы
- `src/index.{ext}` — "hello, world" (простейшая точка входа)
- `tests/unit/` — тест, проверяющий вывод "hello, world"
- `guidelines/build-run-tests-guidelines.md` — команды сборки/запуска/тестов

{если gui или cli: - `guidelines/ui-style-guidelines.md` — принципы UI/UX-дизайна}

### Статус готовности
- [x] Зависимости установлены

- [x] Сборка прошла успешно
- [x] Тесты прошли
- [x] (Опционально) Приложение запустилось

### Следующие шаги
```
