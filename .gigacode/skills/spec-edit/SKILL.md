# Spec Edit

Создание и обновление спецификаций в соответствии с гайдлайнами проекта.

## ⚠️ ВАЖНО: Уточняющие вопросы

**ОБЯЗАТЕЛЬНО** задавай уточняющие вопросы перед созданием или изменением спецификации.
Не додумывай требования — используй `NEEDS_CLARIFICATION` если поведение неизвестно.

## Правила проекта

**ОБЯЗАТЕЛЬНО** следуй гайдлайнам:
- [`guidelines/specification-guidelines.md`](../../guidelines/specification-guidelines.md) — структура, ID, правила написания
- [`guidelines/implementation-guidelines.md`](../../guidelines/implementation-guidelines.md) — связь spec ↔ реализация
- [`guidelines/documentation-guidelines.md`](../../guidelines/documentation-guidelines.md) — структура docs/, фронтматтер

## Сценарии

### 1. Создание новой спецификации

```
создай спецификацию для {описание функциональности}
```

1. Определи домен и имя файла
2. Задай уточняющие вопросы (см. `references/workflows.md`)
3. Напиши spec по структуре
4. Проверь качество (чек-лист)
5. Предоставь пользователю на утверждение

### 2. Обновление существующей спецификации

```
обнови спецификацию {spec-name}
```

1. Прочитай текущую spec
2. Определи что изменилось
3. Задай уточняющие вопросы по изменениям
4. Определи новый статус (см. `references/workflows.md`)
5. Обнови spec
6. Проверь на противоречия с другими specs
7. Предоставь пользователю на утверждение
